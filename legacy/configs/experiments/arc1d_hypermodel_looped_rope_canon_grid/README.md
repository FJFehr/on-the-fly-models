# arc1d_hypermodel_looped_rope_canon_grid

## Goal

`arc1d_hypermodel_looped_rope_canon_mechanism_ablation` isolated `gradient_clip_val` (5 vs 10)
alone at rank=8, and it recovered most of the gap between the followup experiment's strong
result and the weaker rank_sweep result (mean `val_query_exact_match` 0.746 to 0.837),
while pooling alone barely moved it (0.746 to 0.773). But a third difference,
`hyper_model.num_layers` (2 in the followup experiment, 4 in every experiment since), was
never isolated, so layers and clip may interact rather than act independently. This
experiment runs the full layers x clip grid to find out, and crosses in the
mechanism_ablation experiment's other strong finding (removing the task descriptor cost
about 0.12 exact match) across every cell, since that effect might also depend on layers or
clip rather than being constant.

## Grid

| Axis | Values |
|---|---|
| `hyper_model.params.num_layers` | 2, 4, 8 |
| `gradient_clip_val` | 5, 10, 20 |
| `hyper_head.num_tasks` | 18 (task descriptor present), `null` (absent) |

3 x 3 x 2 = 18 configs (`cell_l{2,4,8}_clip{5,10,20}_{td,notd}.yaml`), generated by
`scripts/gen_hypermodel_looped_rope_canon_grid_configs.py`. 3 seeds each, 54 jobs total.

Fixed across every cell: RoPE+Canon encoder (`rope_canon_transformer`, `canon_set=ABCD`),
attention pooling only (no hierarchical: confirmed no benefit in the followup experiment and
barely-there, higher-variance benefit in the mechanism_ablation experiment),
`lora_adapter_rank=8` (confirmed the winning rank in the rank_sweep experiment), target model,
17-task list, `N_supervision=2`, `batch_size=512`, `max_steps=4000`/`warmup_steps=400`.

## Running

```bash
# Regenerate the 18 leaf configs if base.yaml or the generator script changes:
uv run python scripts/gen_hypermodel_looped_rope_canon_grid_configs.py

# Full grid (18 configs, 3 seeds each, 54 jobs total).
bash scripts/run_hypermodel_looped_rope_canon_grid.sh
```

No overfit smoke configs this round, matching the last three experiments; running directly on
the cluster (`torrnode12.priv`).

## Reading results

Compare `val_query_exact_match`/`test_query_exact_match` (mean plus-minus std across 3 seeds)
as a 3x3 heatmap (layers x clip) for each task-descriptor setting, per task and averaged.
Specifically:

- Does `num_layers=2` (matching the followup experiment) beat `num_layers=4`/`8` at every
  clip value, or only at `clip=10`? If the advantage only shows up at `clip=10`, that is
  direct evidence of a layers x clip interaction rather than two independent effects.
- Does raising `gradient_clip_val` from 10 to 20 keep helping, plateau, or reverse (loosening
  clipping too far could reintroduce the loss-spike instability the original 10.0 value was
  chosen to guard against)?
- Does the task-descriptor gap (`td` vs `notd`) hold constant across the grid, or shrink at
  settings that otherwise train better (i.e. is the "oracle label" less necessary once the
  rest of the setup is tuned well)?
