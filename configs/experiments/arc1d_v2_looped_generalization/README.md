# arc1d_v2_looped_generalization

## Goal

Same question as `arc1d_hypermodel_looped_rope_canon_generalization`: can the hypernetwork
generalize to a task category it has never seen during training, inferring the task purely from
the 3-shot support examples at inference time -- and does a task-identity signal
(`hyper_head.num_tasks`, learned vs. frozen) help or actively hurt that generalization?

This is a rerun of that question at the **dim=4 main-grid architecture from
`arc1d_v2_hypernetwork_multitask`** (`dim4_notd.yaml`/`dim4_frozentd.yaml`) rather than the
original experiment's much bigger `rope_canon_zhu_transformer`/hidden_dim=64, 8-layer, ~1.58M-param
recipe. This is a smaller step down than `arc1d_v2_compositional_generalization`'s "matched-scale"
architecture (10,156 params, `bottleneck_dim=8`) -- here the target model is the same 1,398-param
dim=4 size, but the hypernetwork encoder and bottleneck stay at the v2 main-grid's standard size
(`hidden_dim=32/num_layers=2/output_dim=64`, `bottleneck_dim=128`, ~200K total params), not the
further-shrunk matched-scale variant.

## Reusing the original experiment's design

Nothing about the *task* changes, only the architecture:

- Same 5 held-out categories, same siblings, same rationale for the choice (a structurally
  similar category left in training) -- see
  `arc1d_hypermodel_looped_rope_canon_generalization/README.md`'s "Held-out tasks" table.
- Same mechanism: each leaf's `task_categories` drops exactly one of the 15 categories (the
  held-out one) while `val_task_categories` keeps the full 15, so `results.txt`'s automatic
  per-category breakdown (`val_query_exact_match_by_task_<category>`,
  `val_query_accuracy_by_task_<category>`) reports both the held-out category's zero-shot score
  and the 14 in-distribution scores from the same run.
- Config naming: `arm_<short_name>_<variant>.yaml`, generated by
  `scripts/gen_v2_looped_generalization_configs.py`.

## Architecture

| Component | Value |
|---|---|
| Target model | `rope_canon_looped_transformer`, `hidden_dim=4`, flat (`n_loops=1`) -- 1,398 params |
| Hypernetwork encoder | `rope_canon_transformer` (plain, non-Zhu), `hidden_dim=32, num_layers=2, output_dim=64` |
| `hyper_head.bottleneck_dim` | 128 |
| Generation | Dense (`lora_adapter: false`) |
| Optimizer | Muon (`muon_lr=0.005, muon_momentum=0.95`) + AdamW aux (`lr=0.001, wd=0.01`) |
| Budget | `N_supervision=1, max_steps=8000, warmup_steps=800` |
| `save_checkpoints` | `false` -- unlike the compositional-generalization experiments, the
held-out score comes from this run's own validation loop, no separate eval script/checkpoint needed |

## Arms

Same 3 variants as the original experiment, 5 held-out categories each = 15 jobs (per seed):

| Variant | `hyper_head.num_tasks` | `hyper_head.freeze_task_indicator` |
|---|---:|---:|
| `notd` | `null` | `false` |
| `td` | `18` | `false` |
| `frozentd` | `18` | `true` |

## Running

```bash
# Default: seed 1 only, all 15 arms.
bash scripts/run_arc1d_v2_looped_generalization.sh

# Split across nodes / add seeds, same convention as the original experiment:
SEEDS_OVERRIDE="2" bash scripts/run_arc1d_v2_looped_generalization.sh
```

## Reading results

Same as the original experiment: pull `val_query_exact_match_by_task_<held_out_category>` and
`val_query_accuracy_by_task_<held_out_category>` out of each arm's `results.txt`, and compare
`notd`/`td`/`frozentd` at this much smaller scale against that experiment's findings (exact match
~0 for 4/5 held-out categories under every variant; the `1d_denoising_mc` exception favoring
`frozen_td`).
